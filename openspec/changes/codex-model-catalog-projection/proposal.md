## Why

Codex falls back to incomplete metadata when a provider adds a namespace to a
model ID that the installed client knows only by its base slug. AIGW needs a
client-bound projection that restores the client's own metadata without
changing the model sent to the provider or taking ownership of user catalogs.

## What Changes

- Generate a complete Codex model-catalog mirror with namespace aliases derived
  from the selected model ID and the installed client's bundled catalog.
- Bind generated bytes to the exact Codex version and executable digest.
- Project the catalog, configuration reference, and sidecar in one compensated
  transaction with owner-only permissions.
- Add a tracked real-client verification command that performs no model request.
- Restore the intended aggregate coverage veto while retaining mandatory
  package observation and exact package diagnostics.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `product-control-plane`: Extend transactional Codex projection to an owned,
  client-bound model catalog and a real-client verification boundary.
- `product-quality`: Align executable coverage admission with the established
  aggregate-risk contract and mandatory package observation.

## Impact

The change affects Codex projection and validation, guarded file transactions,
the developer verification tool, coverage policy, tests, and their canonical
documentation. It adds no provider-specific core path, runtime dependency,
network request, client lifecycle ownership, or compatibility surface.
