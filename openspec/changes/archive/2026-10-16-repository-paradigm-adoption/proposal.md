# Proposal

## Why

The accepted ETHOS runtime now reports 44 repository-paradigm gaps before it can prove AIGW's signed OpenSpec archive successor. The native repair removes branch-role fields that AIGW's CUE projection still requires, so applying that plan alone would break CI generation.

## What Changes

- Consume the shared accepted and release roles in the existing CUE projection without a second configurable branch policy.
- Move the diagnosed native tool carriers to their consuming owners and update their existing readers, fixtures, tasks and current documentation together.
- Bind the existing Prettier and Taplo commands to their declared native configuration; preserve formatting settings, quality thresholds and ignored immutable history.
- Apply the native front-matter and workspace repairs, reconcile the GitLab remote name, and normalize Changelog headings while preserving historical content and published objects.
- Prove and deliver the archive successor through the existing signed workflow. Keep original release bytes, installed-client acceptance, failed evidence and foreign lanes with their current consumers.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `repository-organization`: consume shared governed roles and native tool configuration through one portable contribution path.

## Impact

This is an AIGW repository-adoption change in the existing Responses closeout Work Lane. Its scope is the diagnosed `.config/` and `.ethos/` carriers, their existing `tools/ci`, Forge-verification and release-construction consumers, current documentation, Changelog, and this Change. It changes no provider, model, credential, application session, published tag or original release artifact. ETHOS owns the common contract; AIGW owns its projection and configuration consumers. Separate product releases and the ETHOS custody implementation retain their original owners.
