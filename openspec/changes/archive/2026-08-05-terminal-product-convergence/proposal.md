## Why

AIGW must converge as a small provider control plane for native Codex and Claude
Code rather than absorb transport, foreign-application, workstation, or publication authority.
The current candidate closes hosted provenance and native Codex Home defects,
but the product carrier must also prevent provider-identity hacks, cross-cutting
client switches, local hard-coding, and competing delivery shapes.

## What Changes

- Keep AIGW as one native executable owning Accounts, credentials, Profiles,
  Routes, provider policy, and admitted native Codex and Claude Code adapters.
- Make an ordinary provider a token-free manifest extension; keep optional
  provider-native diagnostics as separately admitted leaves.
- Replace provider-name-triggered Codex storage behavior with an explicit
  supported client capability or remove it when the admitted Codex contract has
  no such projection.
- Make Codex and Claude Code cohesive adapters with their own discovery,
  configuration or process plan, authentication, rollback, verification,
  status, and owned uninstall boundaries. Preserve a bounded adapter admission
  seam for future Hermes or other third-party-LLM agents without implementing
  them in this change.
- Keep Responses transport, replay, retry, rate limits, deployment, and service
  lifecycle in the independent Proxy product.
- Keep foreign applications and integrations outside AIGW and Proxy dependency,
  implementation, verification, and release acceptance.
- Preserve the hosted Forge trust projection, portable path grammar, shared
  native Codex Home, current stable supply chain, and absent-client no-op.
- Converge logical and physical ownership, remove forwarding/compatibility
  residue, and require package plus aggregate coverage strictly above 95%.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `product-control-plane`: subject=AIGW terminal provider and native-client
  control plane; reuse=extend; change=modify; define declarative provider
  extension, independently admitted Codex and Claude Code adapters, product
  boundaries, repository supply chain, publication trust, and terminal lane
  state; facet:lifecycle=setup,repair,verification,release,closeout;
  facet:surface=cli,configuration,ci,documentation;
  facet:authority=product-source,operator-input,publication-context.

## Out of Scope

- Responses request transformation, replay repair, retries, cooldowns, listener
  operation, service supervision, or Proxy installation.
- Discovering, configuring, aligning, verifying, repairing, or controlling
  foreign applications or their private runtime state.
- Rewriting Codex JSONL, SQLite, historical messages, Responses item records,
  conversation models, or model metadata.
- Encoding a contributor identity, home directory, repository path, provider,
  endpoint, credential, key, fingerprint, Forge coordinate, or trust anchor as
  a product default.
- Preserving an obsolete command, package, schema, alias, forwarding wrapper,
  or compatibility surface solely because an older release or lane contained it.
- Claiming hosted CI, publication, installation, runtime acceptance, exact
  original-conversation continuity, or housekeeping before fresh proof.

## Impact

Configuration and manifests, provider diagnostics, native client adapters,
Codex projection policy, command composition, package layout, verification,
CI, release assets, docs, and repository-family topology may change. This is an
authorized breaking reconstruction: retained behavior must be re-proved under
one terminal owner rather than carried through compatibility residue.
