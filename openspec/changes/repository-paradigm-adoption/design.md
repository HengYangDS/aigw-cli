# Design

## Ownership and Scope

The installed ETHOS repository paradigm owns shared branch roles, carrier placement and common formatting settings. AIGW's existing CUE projection, source-quality commands and release construction own consumption. The native `lane repair-paradigm` preview supplies deterministic edits; its nine report-only gaps require consumer-preserving migration here.

The archived `terminal-product-convergence` task identities and acceptance remain unchanged. This Change carries only the newly exposed adoption work, with `tasks.md` as its checklist. Git, existing CI and native evidence retain history; no parallel progress store is introduced.

## Native Configuration Migration

Native tool settings move without a policy change. Use the catalog's native basenames under the consuming tool, and keep repository-specific SCC parameters in its existing policy shape. Update all current consumers and fixtures; archived originals retain their bytes. Prettier and Taplo read their new native carriers explicitly and refuse missing or malformed input. Existing formatter fix/check commands retain one inventory and their current settings.

Before writing, bind exact paths to passing lane prewrite. Capture the current native configuration, generated Forge files and Git remote metadata as recovery inputs in the existing evidence directory. Compare parsed settings and unchanged generated projections after migration. A source-tree backup is evidence for this transition, not another live configuration.

## Branch Roles and Publication

The shared roles are accepted `dev`, release `main`, candidate `candidate/dev`, and the shared work/proposal prefixes. The existing CUE model projects exact accepted/release values from that fixed contract; competing workspace values cannot unify. It keeps the native workspace input for the remaining binding, not as a configurable legacy-role authority. Qualify the reduced workspace input and verify that both Forge projections remain byte-identical for the current roles before applying the native repair.

The independent Forge commit verifier also reads the retired `subject_pattern`. Migrate that original owner to the shared subject grammar and optional native scope restrictions in the same batch. Its selected revision, range, identity, SSH-signature and compare-and-swap checks remain required. No arbitrary regex fallback or parallel generic verifier replaces it.

The existing release-readiness parser consumes the bracketed Changelog grammar. Migrate its current construction and command fixtures with the headings; retain exact version/date lookup, tag provenance, chronology and historical yank semantics. Changelog body text and published source objects remain preserved.

Rename only the observed GitLab remote alias after checking current users and the peer binding; retain its exact transport URL and credentials. Other agents' refs, lanes and pending effects are preserved. Any concurrent base movement requires native refresh and renewed admission.

## Acceptance and Delivery

Run the focused projection/configuration regressions, native real-file formatter fix/check and a second unchanged check, strict OpenSpec validation, and a native paradigm report with no diagnosed gap. Freeze signed source and obtain exact-head proof. Implementation checkboxes qualify those inputs; the native lifecycle separately owns this Change's landing, archive and Lane retirement. Reuse unchanged release and installed-client evidence; a repository proof is not new product acceptance.

After implementation acceptance, the Responses migration owner lands the signed source through current native admission. The original AIGW landing owner publishes the same object to both selected peers, verifies each peer's own readback and CI, and retires its original convergence Lane. Archive this adoption Change only after its native prerequisites, verify the resulting source, and retire this exact owned Lane only after byte-preserving custody and consumer release. Preserve those delivery commitments until the native lifecycle closes them; no checkbox records its own lifecycle effect as completed.

Heavy gates respect the existing shared-host measurement window. Evidence custody and lane retirement follow the accepted native owner contract: compare preserved bytes and consumer bindings before releasing any original. Failed receipts, original signed releases and foreign state are retained until their consumers explicitly finish.
