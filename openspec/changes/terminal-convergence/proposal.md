# Terminal convergence

## Why

AIGW already owns the core Codex and Claude Code configuration model, but
historical Work Lanes still carry overlapping CI, release, client projection,
repository organization, and history-governance experiments. Those lanes are
not product authority and must be reduced to the unique behavior still missing
from current `dev`.

## What changes

- Audit every remaining Work Lane, rebuild only uniquely valuable semantics,
  and discard duplicated carriers and obsolete compatibility paths.
- Keep Accounts, credentials, Profiles, Routes, and client adapters as one
  portable configuration control plane.
- Preserve independent Codex and Claude Code projection, safe behavior when a
  client is absent, and low-cost declarative provider extension.
- Converge quality, documentation, supply chain, local release, and independent
  GitLab/GitHub delivery around one proved source revision.

## Non-goals

- No proxy lifecycle, API traffic, JetBrains configuration, Workstation state,
  Codex transcript, JSONL, SQLite, history, or model-metadata ownership.
- No shell interception, forwarding facade, compatibility package, personal
  identity, host path, or Forge-specific product behavior.
- No history rewrite in the product delivery critical path.
