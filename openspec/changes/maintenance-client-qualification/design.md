native commands and real temporary Stores. Verify ordering, fallback promotion,
and unrelated state rather than asserting private implementation counters or
adding error fixtures solely for coverage.

Hermes configuration owner prepares one isolated verification home and retains
the original credential-command projection. Reuse the official launcher's
dependency selection metadata and immutable installed inputs, including the
selected profile/plugin members; keep boot records, sessions, and generated
configuration private to verification. The launcher continues to select and
lease its own environment. Do not pin an environment generation, copy complete
operator configuration, or introduce package-manager orchestration.

and the physical selection lock, while private boot records remain disposable.
The inference policy disables lazy installation, update checks, PATH
publication, plugin activation, and active memory providers. The original
bootstrap no-install environment guard is retained. Windows refuses native
verification before starting a child; configuration projection remains
available under its existing contract.

The maintenance source remains descended from signed 0.3.4. Current 0.4.0 refs,
its separate verification work, and all historical signed tags stay preserved.
The implementation owns no new specification behavior, so this Change uses
the native `skip_specs` contract.
