# AIGW CLI v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver an installable cross-platform CLI that securely manages provider profiles, inherited client routes, OS secrets, and Claude/Codex adapters without a background service.

**Architecture:** A small Go binary owns a TOML control plane and delegates secret persistence to an interface backed by each OS credential store. Domain routing stays independent of client adapters; adapters receive an already-resolved profile and project only AIGW-owned state at their client boundary.

**Tech Stack:** Go 1.25+, Cobra, Lip Gloss, Huh, go-keyring, go-toml/v2, GitLab CI, GoReleaser-compatible release metadata.

## Global Constraints

- Product command is `aigw`; repository is `aigw-cli`.
- One profile has exactly one logical secret at `AIGW_TOKEN/<profile-id>`.
- Tokens never enter TOML, command arguments, logs, JSON output, documentation, or backup files.
- macOS, Linux, and Windows are first-class targets on amd64 and arm64.
- No daemon, watchdog, local listener, launchd unit, systemd unit, or scheduled task.
- Claude and Codex adapters must not write into each other's namespaces.
- No `dmx-*`, `init-dmx`, or `apply` compatibility commands.
